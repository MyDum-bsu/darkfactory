# Фабрика Board + BB

Этот репозиторий — актуальный исходник новой фабрики. Board хранит задачи и зависимости; BB исполняет; Git SHA и квитанции подтверждают результат.

## Как работать

1. Уточни результат и критерий в **одной** карточке Board; бери только согласованный scope. Готовая задача — явная граница между обсуждением и исполнением.
2. Работа — в feature-worktree. Один писатель на рабочую копию; перед новым worktree/сборкой пройди дисковый preflight. Сдача указывает карточку, попытку и точный чистый SHA, со всеми нужными файлами.
3. Проведи проверки из доверенного профиля и независимое ревью того же SHA. Исполнитель не принимает свою работу; завершение хода BB не доказывает сдачу/приёмку.
4. **Правило «Шивы»**: одна задача/веха = один свежий чистый контекст Лида. По закрытии итог фиксируется в Board и Project Memory, тред останавливается; на следующую задачу стартует новый чистый Лид строго по Board, Project Memory и Owner Decision Ledger. Вся кодовая работа — только через принятый контроллер (`run-isolated.mjs` / `daemon.mjs`), без ручного `bb thread spawn`.
5. Политика выпуска отдельно от ревью: действующие branch checks обязательны, выпуск/мердж/push/CI и запись в рабочие данные только по соответствующему допуску. Если нужен владелец — один конкретный вопрос с действием и доказательством.

## Куда смотреть

- **Вход лида: идея, grill, to-spec, вопрос P1.1** → [стандарт intake: сверка решений владельца и спека](docs/lead-intake.md). Применимые решения сверяются до вопроса и передаются в согласованном поручении, без доступа воркера к базе.
- **Реализация или исправление пайплайна** → [порядок, интерфейсы и сценарии отказа](docs/implementation-plan.md). P0.1 в базе; начать следующий этап только после согласования scope.
- **Проверка установленной среды** → `npm run doctor`; тесты → `npm test`. Тяжёлый стенд — отдельно по preflight.
- **Правки локальной обвязки** → `ops/local/` — версия исходников. Действующая Board и её данные находятся вне Git. Подключение только явно; не подменять установленный runtime по ходу тестов.
- **Почему устроено так** → [происхождение, подтверждённый статус и исследование](docs/STATUS.md).

## Границы

Одна очередь — Board. Старые `stg`, `factory/book.py`, диспетчер и их worktree — архив, не источник новых задач. Не сбрасывай и не перемещай чужую работу. Рабочие БД, токены, сессии BB, профили браузера и build-артефакты остаются вне репозитория. Код от воркера не получает полномочия из текста карточки или сдачи.
