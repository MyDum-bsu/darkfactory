# P2.2: наблюдение после выпуска (#838)

Один явный foreground-тик `node board_pipeline/run-release-watch.mjs --policy /operator/watch.json` для изолированного T4. Оператор указывает один завершённый релиз. Наблюдатель сверяет native-карточку `pilot` с `ReleaseReceipt`, затем делает только `GET /version` и `GET /artifact` на закреплённом экземпляре loopback-цели. Зелёный тик не пишет на Board и не запускает модель.

## Сигнал и приёмка

Дымовой сценарий после выпуска: пользователь должен получить тот же статический артефакт как `text/plain; charset=utf-8`. Формат HTTP-ответа может испортиться без изменения опубликованных байтов; поэтому повтор проверки только SHA или префикса содержимого недостаточен. Красный сигнал — успешный ответ с валидной идентичностью *и* байтами релиза, но неверным `Content-Type`. Ошибка источника, подмена байтов, смена экземпляра или выпуска не доказывают регрессию: тик завершается ошибкой без создания или правки инцидента.

| Сценарий | Проверяемый эффект |
|---|---|
| Нет подтверждённого `deployed` или версия не совпала | Нет инцидента; нет claim и вмешательства в выпуск |
| Зелёный ответ на подтверждённой версии | 0 записей и 0 запусков модели |
| Повтор красного ответа, в том числе после перезапуска | Та же запись Board, обновляется время подтверждения; fingerprint не включает время |
| Потерян ответ `post` или одновременное наблюдение | Ключ клиента Board тот же; не создаём второй корень |
| Лид взял карточку в работу или уже отредактировал её | Наблюдатель не затирает текст лида и не меняет статус |

## Запуск в изоляции

Оператор заранее создаёт канал `intake` на отдельной loopback Board и сохраняет локальную политику вне worktree. Укажите точную карточку **подтверждённого** T4-релиза из канала `pilot`, её владельца и `repo_id`, цель и экземпляр из доверенного `GET /version`:

```json
{
  "boardUrl": "http://127.0.0.1:44980/api/board",
  "url": "http://127.0.0.1:44981",
  "releaseTask": "101",
  "owner": "local:user:operator",
  "repo": "fixture-repo",
  "target": "isolated-t4",
  "instance": "abcf1234-0000-4444-1111-123456789abc"
}
```

Передайте через локальное окружение `DF_WATCH_BOARD_TOKEN` для изолированной Board. Токен в файл политики и карточку не попадает. Не подставляйте боевой или операторский ключ выпуска. На каждую операцию порт применяет `x-board-can` (`pilot=read;intake=read,post`) и постоянный профиль `release-observer`; для стабильного дедупа не меняйте эту идентичность на той же Board. Сужение запроса не меняет права исходного токена: храните его вне воркеров. У порта только чтение, создание локального сообщения и редактирование его текста, без методов task API.

Граница ключа — репозиторий, цель, экземпляр, SHA, digest, операция и класс симптома. Зелёный тик ничего не закрывает; для нового выпуска оператор явно меняет выбранную карточку. При ошибке источника либо неопределённом результате записи тик возвращает ненулевой код; повтор — отдельный тик по тому же ключу, без слепого повтора `post` внутри команды. После того как лид уточнил текст или превратил инцидент в задачу, наблюдатель больше не перезаписывает это поручение.

## План и границы

1. Вынести общий запрос и привязку версии/байтов из T4 в read-only порт. Изменить только путь чтения, сохранить сигнатуры приёмки, выпуска и отката. Сценарии T4 остаются в `npm run test:integration`.
2. Тик P2.2 сверяет завершённый релиз и подтверждённый HTTP-ответ. Только на красном результате обновляет локальный корень в канале `intake`, без sync, меток запуска, release grant или native task mutation. Лид оформляет задачу обычным путём.
3. Ключ `df-p22-<fingerprint>` хранит сама Board (native client ID), без второй очереди. Обновление только собственной карточки с compare-and-set по ревизии; если результат записи неизвестен, не повторяем запись внутри тика.
4. Unit-проверки решения тика и интеграция с настоящей изолированной Board и HTTP-целью. Чистовой прогон: `npm test`, `npm run test:integration`, `npm run test:tla`.

Работа не подключает `:44100`, не планирует фоновый процесс и не меняет активную политику. Доступ к каталогу цели, worktree релиза, ключу владельца и модели не нужен.
