# #1448 — контракт измерения A/B

Только утверждённые две задачи на санитизированной копии Darkfactory. A: малый валидатор policy ID с unit-тестами. B: договор сдачи с коротким руководством и исполняемой проверкой. По одному запуску каждой задачи в arms `v1.5` и `v2`. Один и тот же исходный Git-снимок, текст задачи, допущенная триада и независимые проверки в паре; чередование порядка A/B. Ни живых данных, ни переключения runtime. Worktree изолирует изменения Git, не является OS sandbox; в него передаётся только явно утверждённое содержимое.

Граница пилотного адаптера: единственный пишущий BB-тред принадлежит попытке Trust Kernel. Foreman вызывает отдельные наблюдения с Stage Skills на утверждённых фактах артефакта, после привязки SHA, аренды, switch и пинов. BB verdict привязан к конкретному запросу, checkpoint, дочернему треду и digest; модель не является источником самостоятельно объявленных счётчиков. Неизвестный результат spawn сохраняет intent, без автоповтора. Отдельная штатная независимая L2-проверка и native complete остаются обязательны. Все размещения явно выбираются оператором.

Гейт измерения: сначала неизменные входы и stop limit, потом ровно четыре выделенных запуска на временной Board. Не смешивать тесты адаптера и model evidence. Для каждого arm извлечь подтверждённую native-сдачу, первый раунд, число REWORK, полный wall-clock, токены и фактическую стоимость; неполное покрытие — `null`, не ноль. Сравнить через `telemetry-collector.mjs` и `diffSnapshots`; на двух задачах не заявлять статистическое превосходство. Если этап, среда или доказательства недоступны, сохранить наблюдаемый стоп и No-Go вместо недоказанного успеха.

Приёмка: unit/интеграционные проверки guard и доказательств, фактические четыре запуска только при готовом безопасном стенде, ревью того же SHA. Службы, рабочая Board и живые данные не меняются.
