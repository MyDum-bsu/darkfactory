# Операторская фикстура живого VS-1 E2E

Живой прогон требует отдельного допуска на BB и модельное ревью; `npm run test:integration` его не запускает. Выберите одноразовое синтетическое дерево без рабочих данных, приватного кода или секретов, не разрешённых к передаче моделям.

```sh
node board_pipeline/vs1-e2e-runner.mjs --execute \
  --lab-parent "$LAB_PARENT" --fixture "$FIXTURE_FILE" --proof "$PROOF_FILE"
```

Все три пути абсолютные, вне tracked-дерева. `LAB_PARENT` — каталог под изолированный клон и тестовую Board с preflight ≥ 8 GiB. `TMPDIR` должен быть на ФС с POSIX-правами. Файл доказательства и журналы оставляйте в приватном хранилище. Runner создаёт собственный конфиг Board для loopback-стенда; порт можно выбрать через `--port`, порт рабочей Board запрещён.

Операторский JSON (не включать в Git):

| Поле | Значение |
|---|---|
| `repo`, `bundle` | Абсолютные пути к локальному репозиторию и Git bundle с объектами кандидатов, доступными по тегам. |
| `base`, `defect`, `final`, `finalTree` | SHA-1: три различных коммита и ожидаемое дерево финального кандидата. База красная на L1, дефект проходит локально и блокируется L2, финал проходит приёмку. |
| `bbProject` | ID отдельного проекта BB для допущенной синтетики. |
| `reviewPrompt` | Абсолютный путь к приватной политике независимого ревью фикстуры: правило для заданного дефекта, read-only границы и требуемая квитанция. |
| `checks`, `visual` | Непустой список локальных проверок и один визуальный шаг по обычному профилю `{image, argv, cwd, timeoutMs, mounts?, env?}`. Укажите существующие локальные образы; runner закрепит их digest. `cwd` относителен к снимку. |
| `allowTestDeletion` | Необязательный явный допуск к изменению защищённых тестов только для согласованной фикстуры; по умолчанию выключен. |

Сценарий сверяет последовательность L1 → L2 rework → verified, разблокировку зависимости и пустой тик без BB, Docker или модели. Невозможность воспроизвести ход не является подтверждённой сдачей.
