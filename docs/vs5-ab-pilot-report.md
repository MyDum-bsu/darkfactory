# VS-5.2 (#1448) — A/B-пилот

**No-Go на включение v2 в рабочем runtime.** Из четырёх назначенных запусков закрылась одна карточка в линейном arm. Ни один запуск Foreman не дошёл до порта stage observations. Живой BB-адаптер подключён за явным флагом изолированного пилота и проверен контрактными тестами, но его полный живой маршрут этим экспериментом не подтверждён. Это не оценка превосходства алгоритмов: две пары, разный момент отказа и одинаково важные инфраструктурные стопы.

## Что сравнивалось

- A — чистый policy-key validator и unit-тесты; B — краткий договор сдачи, JSON-пример и исполняемая проверка. Ровно один запуск каждой задачи в каждом arm, порядок `A linear → B foreman → A foreman → B linear`. Повторов не было.
- Фактические запуски выполнены на `ad09b97cef1c37728fdd3d175c6d72b03db6a5b6`. Линейный контроль использовал код контроллера и приёмки v1.5 `83ffec0796c949e4aed7129cab4c9d6d5e61fcdb` через общую инструментированную изолированную обвязку, без Stage Skills и Foreman. Treatment — та же обвязка плюс skills роли реализации и, при достижении L2, Foreman до вызова независимого критика. Это сравнение маршрутов, не двух неизменённых бинарников.
- Все четыре worktree получены из одного санитизированного дерева, без старой истории. База фикстуры в четырёх случаях `9073862bf95c6fcc150afb2e0cd856478d6519d2`. Парность входов подтверждена по дайджесту базы, брифа, L1-профиля, L2-промпта, рабочих моделей, routing и лимита. Исполнитель Pi/DeepSeek Flash (`opencode-go/deepseek-v4.1-flash`), L2 — Pi/Sol `medium`. Арбитр Google закреплён для независимой триады, но не вызывался. ZCode не запускался, динамическое обучение между ячейками отключено.
- Каждый запуск использовал свою временную loopback Board, приватные операторские входы и один пишущий тред. Worktree разделяет Git-изменения, но не является OS sandbox. Работа шла только с утверждёнными санитизированными данными. Живые Board/runtime и основной checkout не переключались. Измеренные воркеры завершены или явно остановлены; временные Board остановлены.

## Что изменено после измерения

Добавлено ожидание только для настоящего дочернего `starting` без готового workspace; чужой путь и чужой parent по-прежнему отклоняются. Пилотный launcher завершает однозначно свои активные треды при остановке, адаптер сверяет нативный запрос целиком, отчёты берутся из измеренных фактов L1 и Git. Это проверено детерминированно; **четыре живые ячейки не повторялись**. Следующий живой допуск должен подтвердить хотя бы один полный Foreman→BB stage→L2 на том же SHA и парные результаты в отдельной выборке. До этого live runtime оставить прежним.

Воспроизведение после отдельного допуска: `node ops/ab-pilot-run.mjs --execute --case policy|docs --arm linear|foreman --root ABS_PRIVATE_DIR` из уполномоченного родительского BB-треда, затем read-only `node ops/ab-pilot-compare.mjs ABS_PRIVATE_DIR`. Один каталог кампании, каждую ячейку создавать только один раз. Исходные логи и операторские конфиги в Git не включаются.
