# VS-2 T3: допуск пилота P2.1 и фазы в карточке

Этот код не включает рабочую автоматику. Прежний `scope: isolated`, `channel: pilot` по-прежнему запрещает порт `44100`. Новый `scope: pilot` выключен, пока оператор явно не закрепит маршрут и не откроет kill-switch. Для `:44100` дополнительно нужен `--allow-live-pilot` и отдельное решение о подключении. При приёмке T3 не добавлять этот флаг в сервис и не менять конфигурацию рабочей Board.

Фрагмент доверенной политики для **изолированной** Board (порт и идентификаторы берутся из конкретного стенда):

```json
{
  "scope": "pilot",
  "boardUrl": "http://127.0.0.1:44481/api/board",
  "channel": "bgu-cabinet",
  "owner": "local:user:operator",
  "label": { "key": "automation", "value": "bgu-pilot" },
  "route": { "repoId": "bgu-cabinet-repo", "checkProfile": "bgu-verified", "finish": "verified" },
  "pilot": { "enabled": false, "killSwitch": "/operator/private-pilot/switch" }
}
```

Допускается только `bgu-cabinet` / `verified` с точным совпадением владельца, маршрутной метки, репозитория и профиля. Нет режима фиксированной `taskId`, развёртывания или обхода других каналов. Текст карточки и конверт воркера не меняют доверенные параметры. Маршрут не принимает `questionGate`: локальный P1.1 требует эксклюзивного владельца, а в Board 0.54.0 нативный `unblock` не умеет CAS по эпохе и блокировке. Прежний изолированный маршрут P1.1 сохраняется.

## Остановка и восстановление

Kill-switch — обычный файл с одной ссылкой и приватными правами, принадлежащий оператору. Его канонический приватный каталог не пересекается с worktree, каталогом сдачи или контроллерным state. Открывает маршрут только точная строка `run\n`. `stop\n`, отсутствие файла, симлинк, неверные права, неожиданные байты или ошибка чтения закрывают его. Для изменения оператор атомарно переименовывает приватный файл в этом каталоге. Штатная установка не создаёт открывающий файл.

Проверка стоит перед каждым тиком и на границах эффектов: нативные claim, renew, block/complete, метки фаз; spawn и feedback в BB; Docker-проверки, UI и ревью; OAuth refresh, модельный CONNECT и передача промпта Agy. Для эффектов по карточке сверяется фактический допуск и действующая эпоха, а не старая проекция. Уже отправленные операции не откатываются. Намерение и бронь слота сохраняются; повторное включение не доказывает отсутствие старого эффекта и не разрешает слепой повтор. Перед переиспользованием слота сверить состояние по приватному журналу.

## Фазы в карточке

Нативный статус задачи остаётся главным. На том же корне записываются `factory.phase`, `factory.epoch`, `factory.next` и `factory.sha`, если известен проверяемый кандидат. Фазы: `claimed`, `L1`, `L3` (только там, где нужен UI-гейт), `L2`, `L2_REWORK` / `L2_PASS`, `completed` или `blocked`. Исход L2 появляется только после проверки квитанции. Финальная метка появляется после нативного перехода и долговечной записи контроллера. Текст pilot-блокировки фиксирован; сырой stderr, промпты, замечания моделей и claim-токены остаются в приватном журнале. Ручные блокировки в прежнем изолированном маршруте не меняются.

Перед записью адаптер читает текущий нативный статус и эпоху. Условная запись `label.if` сверяет прочитанные метки проекции и маршрута. Она не атомарна с мутацией claim/epoch, поэтому отображаемая фаза не выдаёт полномочий и не доказывает приёмку. Ошибка отображения видна; она не отменяет и не повторяет подтверждённый нативный переход.

Приёмка: `npm run test:tla`, `npm test` и `npm run test:integration` на чистом SHA. Интеграция использует настоящую временную loopback Board и файловую систему, с управляемыми ответами BB и моделей. Трассы проверяют фазы и безопасный blocked, отказ чужим карточкам, разрывы kill-switch перед эффектом и условную запись меток. Это не живой пилот на `:44100`.
