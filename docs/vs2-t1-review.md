# VS-2 T1: независимое ревью и арбитраж

`board_pipeline/run-isolated.mjs` по-прежнему отказывается работать с Board `:44100`. Новый профиль предназначен для изолированного маршрута с нативной очередью и `CandidateSubject`; у него нет `route.taskId` или переопределения `policyDigest`. Ручной `submit` v1 и VS-1 E2E сохраняют свой ранее закреплённый профиль Pi/Sol.

Фрагмент доверенной операторской политики, не содержимое карточки:

```json
{
  "profiles": {
    "code": {
      "review": {
        "provider": "google",
        "model": "gemini-4-neon",
        "reasoningLevel": "medium",
        "skills": ["logika"]
      }
    }
  },
  "reviewSkillFiles": {
    "logika": "/home/mydum/.agents/skills/logika/SKILL.md",
    "humanizer": "/home/mydum/.pi/agent/skills/humanizer/SKILL.md"
  },
  "arbiter": {
    "provider": "openai",
    "model": "gpt-6.2-sol",
    "reasoningLevel": "medium"
  }
}
```

Для текстовых/публичных артефактов назначается профиль с `skills: ["humanizer"]`. Файлы читаются по каноническим путям вне worktree и папки сдачи. Их байты становятся частью доверенной инструкции, а не запускаемым расширением. `policy_digest` на изолированной карточке равен SHA-256 от компактного `JSON.stringify` массива hex SHA-256 файлов в порядке: политика, бриф, промпт ревью, legacy review gate, его `routes.json`, файлы выбранных скиллов в порядке `review.skills`. Контроллер сверяет закреплённые файлы до использования и при seal.

Основной L2 работает через фиксированный HTTPS-вызов Gemini API. Docker готовит только текстовый контекст из `unpackExact`: `/candidate` смонтирован read-only, сеть отключена, каталоги worktree, state, Board и конфиг/ключ модели не монтируются. Хостовой транспорт посылает этот контекст и точный diff без инструментов и без redirect. Использовать только профиль и репозиторий, исходники которого разрешено передавать этому провайдеру. Если контекст превышает лимит 1 МиБ, адаптер отказывает вместо обрезки; для файлов без текстового представления провайдер видит отметку об исключении.

Квитанция различает `modelVersion` из ответа API и запрошенный `thinkingLevel: MEDIUM` в принятом запросе. Gemini обычно не возвращает фактическое значение усилия отдельно; оно засвидетельствовано параметром запроса, а не текстом модели и не количеством reasoning tokens. Транскрипт содержит хэш запроса, ответ и эту отметку об источнике доказательства. Адаптер не считает неподтверждённый результат или HTTP-ошибку вердиктом и не выполняет скрытых повторов.

Sol (`medium` или `high`) запускается существующим изолированным Pi-раннером только для содержательного арбитража. Он проверяет те же закреплённые `subject_digest` и effort; операции с долгоживущим OAuth refresh-токеном остаются на хосте. Sol не является автоматической заменой недоступного Neon.

Проверки: `npm run test:tla`, `npm test`, `npm run test:integration`. Интеграция проверяет реальный Docker с симулированным HTTP-ответом Neon и не заменяет живое доказательство. Для приёмки T1 обязателен `npm run test:live:review` (унаследованный живой Pi-критик, Neon и Sol-арбитр). Целевые команды для диагностики: `npm run test:neon:live` и `npm run test:sol-arbiter:live`. Для первого нужен операторский Google API credential с доступом и квотой на `gemini-4-neon`; для второго нужен разрешённый канал Sol. Артефакты прогонов не попадают в Git.
