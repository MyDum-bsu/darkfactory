# VS-2 T1: независимое ревью и арбитраж

`board_pipeline/run-isolated.mjs` по-прежнему отказывается работать с Board `:44100`. Новый профиль предназначен для изолированного маршрута с нативной очередью и `CandidateSubject`; у него нет `route.taskId` или переопределения `policyDigest`. Ручной `submit` v1 и VS-1 E2E сохраняют свой ранее закреплённый профиль Pi/Sol.

Фрагмент доверенной операторской политики, не содержимое карточки:

```json
{
  "profiles": {
    "code": {
      "review": {
        "provider": "google",
        "model": "gemini-4-neon",
        "reasoningLevel": "medium",
        "skills": ["logika"]
      }
    }
  },
  "reviewSkillFiles": {
    "logika": "/home/mydum/.agents/skills/logika/SKILL.md",
    "humanizer": "/home/mydum/.pi/agent/skills/humanizer/SKILL.md"
  },
  "arbiter": {
    "provider": "openai",
    "model": "gpt-6.2-sol",
    "reasoningLevel": "medium"
  }
}
```

Для текстовых/публичных артефактов назначается профиль с `skills: ["humanizer"]`. Файлы читаются по каноническим путям вне worktree и папки сдачи. Их байты становятся частью доверенной инструкции, а не запускаемым расширением. `policy_digest` на изолированной карточке равен SHA-256 от компактного `JSON.stringify` массива hex SHA-256 файлов в порядке: политика, бриф, промпт ревью, legacy review gate, его `routes.json`, файлы выбранных скиллов в порядке `review.skills`. Контроллер сверяет закреплённые файлы до использования и при seal.

Основной L2 использует `agy 1.5.14`, `--model gemini-4-neon --effort medium`, без прямого Gemini API. Снимок `unpackExact` читается и упаковывается только в офлайн rootless Docker (`--network=none`, `/candidate:ro`). Сам Agy — отдельный **хостовый** процесс в пустом cwd `0500`. Он не наследует `BOARD_TOKEN`, `BOARD_URL`, `BB_*`, пути worktree/state или реальный HOME. Его временный HOME содержит только подготовленную область авторизации; фильтр D-Bus допускает чтение одного явно закреплённого пункта модели (`DF_AGY_KEYRING_ITEM`). `DF_AGY_BINARY` и `DF_AGY_SCOPE_FILE` могут закрепить путь к локальному бинарнику и идентификатор области. Хостовая модельная стадия не выдаётся за ОС-изоляцию всего процесса: маркер квитанции `docker-ro-pack+host-agy-notool-v1`.

`HTTPS_PROXY` / `HTTP_PROXY` остаются у хостового брокера; для отдельного профиля Agy есть доверенная переменная `DF_AGY_HTTPS_PROXY`. У контейнерного Pi/Sol Unix socket не даёт доступа к loopback хоста. Хостовый Agy получает отдельный TCP-вход брокера на `127.0.0.1` со случайным credential на каждый вызов; брокер не передаёт этот credential upstream. В обоих случаях пропускается только `CONNECT` к закреплённым адресам модели. Для Agy `play.googleapis.com:443` и необходимый ему `www.googleapis.com:443` открыты только для bootstrap. После проверенного `init` контроллер отзывает bootstrap CONNECT и останавливает фильтр keyring, включая открытые соединения, до передачи prompt в stdin. До этого в контейнере физически нет кандидата или diff. Использовать только репозиторий, исходники которого разрешено передавать провайдеру; предел 1 МиБ, без тихой обрезки.

Точный `init.model` подтверждается `stream-json`; `medium` записывается как аргумент CLI (`agy_cli_request`), а не как метаданная провайдера. Любой tool event, неизвестный шаг или лишний ход убивает процесс и не даёт квитанции; проверенная квитанция содержит `subject_digest`, хэш запроса и транскрипта. Положительный Neon smoke нельзя заменить симуляцией.

Sol (`medium` или `high`) запускается существующим изолированным Pi-раннером только для содержательного арбитража. Он проверяет те же закреплённые `subject_digest` и effort; операции с долгоживущим OAuth refresh-токеном остаются на хосте. Sol не является автоматической заменой недоступного Neon.

Проверки: `npm run test:tla`, `npm test`, `npm run test:integration`. Интеграция проверяет реальный Docker с симулированным потоком Agy, а детерминированный тест брокера доказывает закрытие сессий `play.googleapis.com:443` до выдачи текста и последующий `403` при новом CONNECT. Для приёмки T1 обязателен `npm run test:live:review` (унаследованный живой Pi-критик, Neon и Sol-арбитр). Целевые команды для диагностики: `npm run test:neon:live` и `npm run test:sol-arbiter:live`. При `agy_auth_unavailable` проверяйте разрешённый пункт авторизации Agy; не подключайте реальный профиль целиком. Артефакты прогонов не попадают в Git.
