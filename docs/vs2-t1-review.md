# VS-2 T1: независимое ревью и арбитраж

`board_pipeline/run-isolated.mjs` по-прежнему отказывается работать с Board `:44100`. Новый профиль предназначен для изолированного маршрута с нативной очередью и `CandidateSubject`; у него нет `route.taskId` или переопределения `policyDigest`. Ручной `submit` v1 и VS-1 E2E сохраняют свой ранее закреплённый профиль Pi/Sol.

Фрагмент доверенной операторской политики, не содержимое карточки:

```json
{
  "profiles": {
    "code": {
      "review": {
        "provider": "google",
        "model": "gemini-4-neon",
        "reasoningLevel": "medium",
        "skills": ["logika"]
      }
    }
  },
  "reviewSkillFiles": {
    "logika": "/operator/review-skills/logika/SKILL.md",
    "humanizer": "/operator/review-skills/humanizer/SKILL.md"
  },
  "arbiter": {
    "provider": "openai",
    "model": "gpt-6.2-sol",
    "reasoningLevel": "medium"
  }
}
```

Для текстовых/публичных артефактов назначается профиль с `skills: ["humanizer"]`. Файлы читаются по каноническим путям вне worktree и папки сдачи. Их байты становятся частью доверенной инструкции, а не запускаемым расширением. `policy_digest` на изолированной карточке равен SHA-256 от компактного `JSON.stringify` массива hex SHA-256 файлов в порядке: политика, бриф, промпт ревью, legacy review gate, его `routes.json`, файлы выбранных скиллов в порядке `review.skills`. Контроллер сверяет закреплённые файлы до использования и при seal.

Основной L2 использует `agy 1.5.14`, `gemini-4-neon` / `medium`, без прямого Gemini API. Контроллер экспортирует точный `unpackExact` во временный каталог вне worktree. Офлайн rootless Docker (`--network=none`, `/candidate:ro`) строит список путей и проверяет ссылки; абсолютные, висячие и выходящие из дерева symlink отклоняются. В задание попадает компактный список или ссылка на полный `files.json` и на полный `diff.patch`. Никакой склейки содержимого репозитория; слишком большой операторский brief отклоняется вместо тихой обрезки. Использовать только репозиторий, исходники которого разрешено передавать провайдеру.

Хостовый Agy запускается в пустом cwd `0500` с минимальным env, без путей worktree/state, настоящего HOME, `BOARD_TOKEN`, `BOARD_URL` и `BB_*`. Фильтр D-Bus допускает чтение одного зарегистрированного пункта модели (`DF_AGY_KEYRING_ITEM`). `DF_AGY_BINARY` и `DF_AGY_SCOPE_FILE` могут закрепить бинарник и идентификатор области авторизации, **не** пароль или хранилище ключей.

`HTTPS_PROXY` / `HTTP_PROXY` остаются у хостового брокера; отдельный профиль задаёт доверенная `DF_AGY_HTTPS_PROXY`. Pi/Sol остаётся контейнерным, с Unix socket. У хостового Agy TCP-вход с одноразовым credential на `127.0.0.1`; он не пересылается upstream. Брокер разрешает CONNECT только к закреплённым узлам. `play.googleapis.com:443` и `www.googleapis.com:443` открыты только при bootstrap, пока данные кандидата находятся вне доступного Agy cwd. После проверенного `init` контроллер отзывает эти туннели и D-Bus фильтр, передаёт точный снимок в cwd и лишь затем отправляет задание.

Защита чтения (#834): Linux Landlock ABI 4+ (x86-64/aarch64) запрещает записи в снимок и чтение файлов worktree/state; процессу нужен лишь закреплённый снимок, временные каталоги и runtime-файлы. TCP ограничен портом брокера. Доверенный `PreToolUse` проверяет имя/аргументы и реальные пути **до** исполнения: только чтение/поиск/список внутри снимка. Конфиги кандидата находятся под `candidate/`, не в корне Agy. `stream-json` повторно ограничивает ту же область; чужой путь, write, shell, сеть, делегирование или неизвестный шаг прекращают ревью с `review_tool_use_forbidden`. Запись pre-hook сверяется с наблюдаемыми шагами; результат без успешного чтения не принимается. До и после сравниваются хэши снимка и worktree.

Точный `init.model` аттестуется в потоке, `medium` фиксируется как аргумент CLI (`agy_cli_request`), а не метаданная провайдера. Квитанция маркируется `docker-ro-pack+host-agy-rotools-v2`, хранит `subject_digest`, хэш запроса и транскрипта, подтверждённые чтения. Положительный Neon smoke нельзя заменить симуляцией.

По доказанному transient-сбою read-only раннера — код выхода 143 (SIGTERM контейнера) или хостовый таймаут exec — контроллер делает ровно один повтор того же вызова L2 (`l2ReviewWithTransientRetry` в `review-runner.mjs`): тот же закреплённый критик, модель/effort и `subject_digest`, без смены воркера и без повтора L1/L3. `runInReadOnlySandbox` помечает результат `timedOut` только по признаку `killed + SIGTERM` хостового exec; произвольный `null` кода, подстрока «143» в stderr, SIGKILL и обычный сбой exec транзиентом не являются. Перед повтором заново доказываются — непосредственно перед dispatch, после проверки субъекта — текущий lease/epoch (свежий `verifyHeld` с renew и допуском `claimed`, а не кэш флага), допуск карточки по владельцу/метке, живые контрактные метки (`repo_id`, `spec_digest`, `policy_digest`, `profile_id`, `finish`, `fixtures_digest`, `has_ui`) против закреплённых при спавне, `guardTask`, daemon- и pilot-kill-switch и закреплённые входы оператора. Проверка субъекта требует канонический зачисленный worktree (подмена симлинком отклоняется), ту же ветку — detached HEAD и ветка на том же коммите отклоняются — чистый HEAD на `candidate_sha` и прежний base-предок. Завершённый или дисквалифицирующий поток при ненулевом выходе транзиентом не считается: аттестационные отказы парсера, явные error-события и сообщения чужой закреплённой модели сохраняются как hold, содержательный REWORK/ESCALATE сохраняется только по доказанному transient-выходу (143 или host-timeout), PASS по грязному выходу и любой нетранзиентный код не дают квитанции — обычный hold. Daemon kill-switch включён и в пре-эффект самого читателя, поэтому второй вызов тоже упирается в действующий стоп-файл. Неуспех любой проверки отменяет повтор; второй сбой уходит в обычный hold. Повтор журналируется одной ограниченной структурной записью (`l2_review_retry` с причиной), без сырого stderr. Детерминированный прогон `board_pipeline/review-retry.test.mjs` (в `npm test`) покрывает оба сценария повтора, отсечение второго сбоя, нетранзиентные и security-отказы, гейты и допуск Neon-профиля; живой Neon здесь не прогонялся.

Sol (`medium` или `high`) запускается существующим изолированным Pi-раннером только для содержательного арбитража. Он проверяет те же закреплённые `subject_digest` и effort; операции с долгоживущим OAuth refresh-токеном остаются на хосте. Sol не является автоматической заменой недоступного Neon.

Проверки: `npm run test:tla`, `npm test`, `npm run test:integration`. Интеграция проверяет реальный Docker с симулированным потоком Agy, а детерминированный тест брокера доказывает закрытие сессий `play.googleapis.com:443` до выдачи текста и последующий `403` при новом CONNECT. Для приёмки T1 обязателен `npm run test:live:review` (унаследованный живой Pi-критик, Neon с реальным чтением нескольких файлов снимка и Sol-арбитр). Целевые команды для диагностики: `npm run test:neon:live` и `npm run test:sol-arbiter:live`. При `agy_auth_unavailable` проверяйте разрешённый пункт авторизации Agy; не подключайте реальный профиль целиком. Артефакты прогонов не попадают в Git.
